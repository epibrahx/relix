# Phase 4 性能验证报告（Spike Report）

> 日期：2026-11-18  
> 结论：**✅ 桌面达标 + WASM 达标 → 继续走 GPUI Kit，桌面与网页共用代码。**

## 1. 测试环境与测试方案

- **硬件 / OS**：macOS (aarch64-apple-darwin, 120Hz 显示器)
- **构建配置**：`--release`（Desktop: `rustc 1.100.0`；WASM: `rustc 1.102.0-nightly` + `wasm-bindgen 0.2.130`，`relix_app_bg.wasm` 20 MiB）
- **数据集**：由 `tools/schemagen` 生成的三档合成 Schema（每表 10 字段、外键密度 1.4）：
  - 100 表 / 140 关系
  - 500 表 / 701 关系
  - 2000 表 / 2781 关系
- **压测方式**：120 帧连续动画循环（前 60 帧平移视口，后 60 帧连续缩放穿过全细节 / 仅表名 / 色块三级 LOD），记录布局耗时、首屏耗时、帧间均值（Mean / FPS）、P95 及单帧 CPU 绘制耗时。

## 2. 渲染优化要点（与最终架构一致性）

1. **单 `canvas` + GPU `paint_quad`**：避免为 2000 张表构建 20,000+ 个 Taffy `div` 节点和 Lyon 路径三角化；卡片、边框、表头及正交连线（含虚线推断边）全部使用 `window.paint_quad` 提交 GPU 实例。
2. **视口裁剪（Viewport Culling）**：`prepaint` 阶段将画布可见矩形映射回世界坐标，只过滤出当前视口内的表节点与包围盒相交的连线。
3. **三级 LOD 降级绘制**：
   - `zoom >= 0.45`：完整表卡片（圆角框 + 表头 + 最多 8 列 `PK`/字段名/类型 + 正交实/虚线）。
   - `0.18 <= zoom < 0.45`：简化卡片（仅表框 + 表名，跳过字段排版）。
   - `zoom < 0.18`：极简色块（纯 `quad` 色块 + 连线，0 次文字排版）。
4. **字号分桶与标签缓存**：预缓存 `SharedString` 并在缩放时按 `0.5px` 取整字号，最大化命中 GPUI `WindowTextSystem` 字形缓存。

## 3. 实测数据汇总

### 3.1 桌面端（macOS Release）

| 规模 | 布局计算 | 首屏渲染 | 平移/缩放平均帧间隔 | 实测帧率 (FPS) | P95 帧间隔 | 单帧 CPU 绘制 | 目标达标 |
|---|---:|---:|---:|---:|---:|---:|:---:|
| 100 表 / 140 边 | 0.1 ms | 0.8 ms | 8.58 ms | **116.6 FPS** | 8.52 ms | 1.84 ms | ✅ |
| 500 表 / 701 边 | 0.2 ms | 0.8 ms | 8.64 ms | **115.8 FPS** | 8.43 ms | 2.27 ms | ✅ (≥55 FPS, <1s) |
| 2000 表 / 2781 边 | 0.7 ms | 2.4 ms | 8.58 ms | **116.6 FPS** | 8.58 ms | 2.14 ms | ✅ (≥30 FPS, 布局<5s) |

> 注：早期未调用 `cx.activate(true)` 时，macOS 后台非激活窗口触发了 GPUI `FramePacer` 的 `InactiveFrameRateLimit`（锁定 30 FPS）；在 `open_window` 后调用 `cx.activate(true)` 即释放全速 120Hz VSync 帧率。

### 3.2 浏览器端（WASM Release，1440×900）

| 规模 | 布局计算 | 首屏渲染 | 平移/缩放平均帧间隔 | 实测帧率 (FPS) | P95 帧间隔 | 单帧 CPU 绘制 | 目标达标 |
|---|---:|---:|---:|---:|---:|---:|:---:|
| 100 表 / 140 边 | 0.1 ms | 0.5 ms | 8.22 ms | **121.6 FPS** | 9.27 ms | 0.96 ms | ✅ |
| 500 表 / 701 边 | 1.5 ms | 6.4 ms | 30.63 ms | **32.6 FPS** | 34.36 ms | 1.77 ms | ✅ (≥30 FPS) |
| 2000 表 / 2781 边 | 1.9 ms | 4.5 ms | 8.02 ms | **124.7 FPS** | 9.31 ms | 1.49 ms | ✅ |

> 注：500 表在首次冷启动页面时包含 WebGPU/管线首次预热开销，均值 32.6 FPS（CPU 绘制仅 1.77 ms）；在随后测试的 100 表与 2000 表规模下稳定跑满 ~121–125 FPS（CPU 绘制 0.96–1.49 ms），交互拖拽与滚轮缩放流畅且控制台 0 错误。

## 4. 决策结论

- 桌面端 500 表 **115.8 FPS**（要求 ≥ 55 FPS）、首屏 **0.8 ms**（要求 < 1 s）；2000 表 **116.6 FPS**（要求 ≥ 30 FPS）、布局 **0.7 ms**（要求 < 5 s）。
- 浏览器 WASM 端 500 表 **32.6 FPS**（要求 ≥ 30 FPS），2000 表 **124.7 FPS**。
- **决策**：采用 **✅ 分支** —— 继续使用 GPUI Kit，桌面端与浏览器 WASM 共用画布与核心/布局代码，进入 **Phase 5（MVP 界面）**。
